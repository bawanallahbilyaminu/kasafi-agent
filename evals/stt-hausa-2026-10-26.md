# Hausa speech-to-text comparison (Oct 26, 2026)

16 of our own voice notes (WhatsApp OGG/Opus, 3.6–22.6 s): Hausa, one English, one Hausa/English code-switch,
and four guardrail questions. Run with `scripts/test_audio.py` (audio converted to 16 kHz mono WAV).
Audio and raw results stay in gitignored `data/test-audio/`.

- **Spark 1.3 / 1.2**: `muse-spark-1.3` / `muse-spark-1.2` with an `input_audio` part, `reasoning_effort=low`,
  asked for transcript + English translation as JSON.
- **VT**: `muse-voice-transcribe-1.0` (Hausa is not in its language list).

Scored by hand on whether the *meaning* survived (✓ right, ~ partly right / garbled spelling, ✗ wrong or empty).

## Findings

1. **No single model is good enough on its own.** Each one fails on notes the others get right.
2. **Spark 1.2** gives the best clean Hausa on long, fluent questions (03, 04, 06, 10, 11), but it fails
   *confidently*: it changes a year (08), inverts meaning (15), and adds names (10).
3. **Spark 1.3** (Meta's docs say its audio support is "not fully supported") often returns empty or cut-off
   output (06, 08, 10, 16).
4. **VT**, despite not listing Hausa, transcribes phonetically and rarely invents content. Its spelling is
   rough and it sometimes drifts into Indonesian, especially on numbers spoken in Hausa.
5. **The guardrails cannot rely on STT alone.** Note 15 (1.2) and note 16 (all three) show the classifier needs
   a fail-safe: unclear audio leads to a clarifying question, never to answering.
6. Years and numbers are where errors cost the most (a wrong year means the wrong document gets fetched).

## Proposed pipeline (adopted Oct 27, see update below)

Run VT and Spark 1.2 audio **in parallel**, then one Spark text call reconciles the two hypotheses into a
Hausa transcript, an English search query and a confidence level. When confidence is low or the two disagree on
a year or number, Kasafi reads back its understanding ("Kana nufin …?") before doing any retrieval.

## Update (Oct 27): combined pipeline scored against the exact wording

Bilyaminu wrote down exactly what he said in each note (`evals/questions.json`). `evals/run_stt_eval.py` runs the
combined pipeline (`app/providers/stt.py`) and has `muse-spark-1.3` judge every system against that reference
(full = 1, partial = 0.5; any wrong year, number, place, document or safety meaning counts as wrong).

| System | Score / 17 |
|---|---|
| Spark 1.3 audio | 9.5 |
| Spark 1.2 audio | 9.0 |
| Voice Transcribe | 11.0 |
| **Combined (VT ‖ Spark 1.2 → Spark 1.3 reconcile)** | **14.5** |

- **Silent errors: 0.** Every note the combined pipeline did not get fully right was flagged for read-back:
  - 04: heard 2021 instead of 2024, flagged as uncertain.
  - 08: dropped "Me" (what); the request itself is intact.
  - 15: "matata" (my wife) became "mata" (a woman); the emergency meaning is intact.
  - 16: dropped "fi" (most); the security topic was recovered, which no single model managed.
- **Read-backs: 9/17.** Four of them (02, 05, 07a, 10) were already correct, so we may tune this down
  later. For now we keep it safe.
- 05 recovered "UNFPA" (heard as "NFT"/"NFE") from the domain vocabulary in the reconcile prompt. That list is general
  Kasafi vocabulary, but it was written after hearing these notes, so treat 05 as optimistic.
- 07b got the previous transcribed question (07a) as context.
- **Latency:** the two hypotheses run in parallel, then the reconcile call; median **8.1 s**, max 12.8 s. Send the
  "Ina duba…" holding reply first.
- Caveat: the judge is the same model family as the reconciler, and n = 17. Re-run when we add more voices (women,
  older speakers, noisy audio).

## Update (Oct 27): Muse Spark Open on Baseten

`meta-models/muse-spark-open-1026` got the same 16 notes as 16 kHz WAV in an `audio_url` base64 data URL part
(`scripts/test_audio.py --provider baseten`), with `reasoning_effort=low` (Baseten's default is xhigh).

| System (second judged run) | Score / 17 |
|---|---|
| Spark 1.3 audio | 10.0 |
| Spark 1.2 audio | 8.5 |
| Voice Transcribe | 11.5 |
| **Spark Open (Baseten) audio** | **7.0** |
| Combined (re-run) | 14.5, 0 silent errors, 9 read-backs |

- **The audio reaches the model**: `prompt_tokens` grows with clip length (376 tokens for 10 s, 498 for 20 s).
  The `audio_tokens` field always reads 0.
- **But the model often ignores it.** On 5/16 notes it answered "no audio provided" or returned an empty
  transcript. Re-running those 5 notes twice each showed this is **random, not a format problem**: the same
  request sometimes transcribes and sometimes comes back empty. Putting the audio before the text made no
  consistent difference, and raw OGG (which Baseten accepts) failed more often than WAV.
- When it does transcribe, its Hausa is weaker than Spark 1.2's (e.g. 04 became "Nafiya's herd", and 10 lost
  "manomi").
- **Decision:** keep Spark Open out of the speech path. Use it for text tasks instead (planning, evidence
  extraction, verification), where it can be compared to Muse Spark 1.3 on the eval set.
- The combined pipeline re-ran at the same score. Per-note verdicts moved slightly (04 is now full; 05 and 07b
  are wrong but flagged), and baseline scores moved by ±0.5, which is the judge's noise level.
